# 程式碼結構

GUI 與命令列共享工具預設和寶可夢準備工作；遊戲模組保留各自的線路格式和時序，共享元件則放在任何遊戲目錄之外。

| 位置 | 職責 |
| --- | --- |
| `pokeldn/app/` | 工具目錄、引數組裝、解析器檢查、設定、路徑與子程序 |
| `pokeldn/popup.py` | 程式在應用中顯示的[彈窗](gui.md#pop-ups)；`pokeldn/app/popups.py` 決定顯示哪些 |
| `pokeldn/pokemon.py` | PKHeX 服務、匯入、最終提供校驗和接收到的檔案 |
| `pokeldn/gifts.py` | 共享的[神秘禮物檔案](gifts.md)封裝、讀取器、寫入器和原生轉換 |
| `pokeldn/receiver_gift.py` | 交換主持方為接收方主機存檔製作的神秘禮物寶可夢（[為接收方玩家制作](gift_simulated.md#made-for-the-receiving-player)） |
| `services/pkhex/` | 固定版本的 PKHeX.Core；合法遭遇生成與相容性檢查 |
| `pokeldn/ldn/` | 無線傳輸、IP、Pia、可靠性與通道表 |
| `pokeldn/online/` | [線上交換](online.md)：中繼、匹配和加密的夥伴通道 |
| `pokeldn/gba/` | GBA 無線連線協議 |
| `pokeldn/gen8.py`, `pokeldn/gen9.py` | 共享的寶可夢記錄編解碼器 |
| `pokeldn/<game>/` | 遊戲標識、訊息、狀態機和協議變體 |
| `pokeldn/launcher.py` | 每個 `bin/` 啟動器共享的標誌（`--keys`、`--phy`、`--capture`、Linux 介面名、`--ip-host`/`--our-ip`），以及被掃描網路的一行描述 |
| `bin/` | 解析器與會話編排 |
| `gui/` | 檢視、控制元件、主題和板子控制 |

應用一次只執行一個會話，因為一塊板子只服務一個程序。在另一個工具上點「開始」會停止
正在執行的會話，等它退出後再啟動；「開始」也會等待正在進行的刷寫。

## 寶可夢準備

每個交換啟動器在開啟無線模組之前，會先通過 PKHeX 服務準備提供的檔案。不相容的格式、
不可用的物種和非法的最終記錄都會被拒絕。會話的訓練家身份絕不會覆蓋匯入寶可夢的原訓練家。

| 行為 | 規則 |
|---|---|
| 分析不完整 | `LegalityAnalysis.Parsed` 為 false 時會重啟輔助程序，並在服務鎖下重試一次；第二次失敗則丟擲異常 |
| 全新身份 | 可選啟用新的 PID 和加密常數；因此變得非法的記錄會保留自己的，並記錄 `the offer kept its own PID` |
| 閃光、單一性別 | 向遭遇請求，因此第三世代的 PID 會保留其 RNG 關聯 |
| 隨機取值 | PID、IV 和野生槽位的等級，每次遭遇最多八次取值 |
| 進化後的物種 | 當沒有以捕獲形態匹配的遭遇時，提升到其進化等級；無性別時（脫殼忍者）取進化後的性別，遭遇的形態不存在時（蔥遊兵）取形態 0 |

在等級或物種變更後失敗的記錄會按順序修復，每一步都基於上一步的結果；保留第一個合法
結果：

1. 僅限 HOME 的事件（劍與盾中的捷拉奧拉、美錄梅塔）在設定為「made」時會獲得 HOME 追蹤器
   （[HOME 追蹤器設定](gui.md#the-home-tracker-setting)）。
2. 招式、回憶招式、TM/TR 記錄標誌、附加招式與精通標誌，以及傳說 阿爾宙斯的尺寸都會
   重新適配。
3. 進化後記錄的特性會在其捕獲時的槽位中重新整理。這一步必須在重新適配之後（傳說 Z-A 中的
   賽富豪）。
4. 沒有經手訓練家的記錄會獲得 `POKELDN`。
5. 計數型進化（擊中要害次數、受到的傷害、憤怒之拳使用次數、硬幣）從它的計數開始。
6. 晶燦鑽石與明亮珍珠中的美麗度進化（美納斯，170）會設定該美麗度，以及它的寶芬所暗示的
   最低光澤度。

無法滿足的請求會被拒絕並給出原因。普通構建只在少數物種上失敗：晶燦鑽石與明亮珍珠 2 種
（時拉比、代歐奇希斯），劍與盾 2 種（蒂安希、美錄坦），傳說 Z-A 1 種（美納斯，其遊戲記錄
拒絕華麗大賽數值），朱與紫 31 種（僅限 HOME 的傳說寶可夢，以及詭角鹿——PKHeX 沒有為其
提供第九世代進化）。

未指定形態的請求會取第一個能構建成功的形態。僅以較晚形態存在的物種：

| 遊戲 | 物種 | PKHeX 可構建的形態 |
|---|---|---|
| 劍與盾 | 基格爾德 | 10%-C、50%-C（群聚變形） |
| 劍與盾 | 瑪機雅娜 | 原始之色，一個事件 |
| 傳說 阿爾宙斯 | 騎拉帝納 | 起源 |
| 朱與紫 | 月月熊 | 血月 |
| 傳說 Z-A | 基格爾德 | 10%-C、50%-C、完全體 |
| 傳說 Z-A | 粉蝶蟲、粉蝶蛹 | 花園花紋、草地花紋 |
| 傳說 Z-A | 彩粉蝶 | 花園花紋、草地花紋、大洋花紋 |

### 遭遇順序

一次構建會逐個版本嘗試 PKHeX 的遭遇（`EncounterMovesetGenerator`），玩家自己的版本優先；
每個版本內按種類嘗試，每種只取前 80 個遭遇：

| 順序 | 種類 | 由此構建的記錄 |
|---|---|---|
| 1 | 野生槽位 | 在槽位的地點和等級捕獲，任意可捕獲的球 |
| 2 | 固定遭遇 | 禮物、傳說寶可夢、團體戰或極巨大冒險寶可夢 |
| 3 | 遊戲內交換 | NPC 的寶可夢 |
| 4 | 蛋 | 孵化，使用其親代遺傳的球 |
| 5 | 神秘禮物 | 排在所有其他種類和版本之後，因為事件的固定 PID 會讓新 PID 的提供變得非法 |

Let's Go 皮卡丘與伊布在自身版本之後還會嘗試 GO 版本：GO Park 園區存放著從 Pokemon GO
帶來的寶可夢，其中包括美錄坦、美錄梅塔和阿羅拉形態。那裡的遭遇選擇是某一種 GO 遭遇
（野生、團體戰、調查等），覆蓋 PKHeX 列出的每個日期視窗。

低於進化等級的已進化寶可夢會先在 100 級測試，然後用二分法找出最低的合法等級。朱與紫中的
蜜集大蛇只在零散的等級上合法。

存檔會清除它收到的、原訓練家的名字、ID 和性別都與自己相同的寶可夢的經手訓練家
（[交換會向收到的記錄寫入什麼](za.md#what-the-trade-writes-into-a-received-record)）。
如果某個構建只有帶經手訓練家時 PKHeX 才接受（例如瑪機雅娜這樣的 HOME 禮物），且其原訓練家
就是玩家，則會以原訓練家 POKELDN、玩家作為經手訓練家來製作；「讓我成為它的原訓練家」會
拒絕這樣的檔案。

### 提供選項

一次構建可以指定形態、性格、特性、性別、攜帶道具、球、親密度、最多四個招式、IV 和努力值、
一個遭遇；在傳說 阿爾宙斯和傳說 Z-A 中還可指定它是否為頭目，在劍與盾中可指定超極巨化因子和
極巨化等級，在朱與紫中可指定太晶屬性。招式、形態、遭遇和頭目會縮小遭遇搜尋範圍；性格、
特性、性別和 IV 會進入遭遇條件。當遭遇得到的是別的結果時，記錄會按玩家的做法修改：

| 差異 | 修改 |
|---|---|
| 性格 | 薄荷，第八世代起 |
| 特性 | 膠囊或膏藥 |
| 要求為 31 的 IV | 極限特訓，在 100 級（第七、八世代）或 50 級（第九世代） |
| 形態 | 在玩家可改變形態的物種上設定，例如洛托姆 |

攜帶道具、球、親密度、努力值、糖飾、超極巨化因子、極巨化等級和太晶屬性都在構建之後設定，
就像使用極巨湯、極巨糖果和太晶碎塊一樣。糖飾是霜奶仙的形態引數，0 為草莓糖飾，6 為緞帶
糖飾；太晶屬性是覆蓋位元組，星晶為 99（`TeraTypeUtil.SetTeraType`）。第三、四世代中高於 100 的
EV 需要相遇後獲得的經驗，因此記錄會得到一點經驗值。傳說 阿爾宙斯的努力等級按遊戲內顯示的
取值，儲存前會減去 IV 偏置（IV 20 起為 1，26 起為 2，31 為 3）。

親密度屬於原訓練家。只有接收方主機的玩家就是原訓練家時，主機才會保留它，因此「設定 →
[你的訓練家](gui.md#your-trainer)」必須是玩家的資訊；每部作品的交換頁面會說明一次交換會
重寫什麼。火紅/葉綠會把收到的每隻非蛋寶可夢設為 70 [trade_scene.c:1071]。

| 選項 | 列出的條件 |
|---|---|
| 球 | PKHeX 至少在一個遭遇中允許它 |
| 頭目 | 傳說 阿爾宙斯或傳說 Z-A 中該物種有頭目遭遇（`IAlphaReadOnly.IsAlpha`） |
| 特性 | 存在攜帶它的合法構建；傳說 Z-A 不列出任何特性 |
| 攜帶道具 | 該遊戲中已解禁的攜帶道具；Let's Go 和傳說 阿爾宙斯沒有 |
| 努力值 | 每項 EV 252、總和 510；Let's Go 為 AV，每項 200；傳說 阿爾宙斯為努力等級，每項 10 |
| 糖飾 | 霜奶仙，且該遊戲的記錄會保留形態引數 |
| 超極巨化 | 該物種和形態滿足 `Gigantamax.CanToggle` |
| 極巨化等級 | 劍與盾，蒼響、藏瑪然特和無極汰那除外 |
| 太晶屬性 | 朱與紫，且該物種的太晶屬性可改變（`TeraTypeUtil.CanChangeTeraType`）；18 種屬性和星晶 |

「最大 IV」把六項都設為 31，「最大親密度」為 255。「最大 EV」會把每項屬性填到上限；在總和
510 之下，該物種基礎數值最高的兩項各得 252，第三項得剩下的 6 點。

### 選擇遭遇

`encounters` 會列出該物種和形態的構建可能來自的每一個遭遇，按[遭遇順序](#encounter-order)
排列，並分組：同一版本、同一地點的同一種遭遇，其所有槽位和等級合在一起；或一張神秘禮物
卡片（`EncounterKey`）。每個分組帶有地點名（`ILocation.GetEncounterLocation`，禮物則為卡片的
標題）、等級範圍、作為進化前形態相遇時的物種，以及是否可以為閃光。給定分組鍵的構建只會
嘗試該分組；構建的回覆會給出它的 `encounter_place`。

會保留[遭遇順序](#encounter-order)中第一個能合法承載所有請求的遭遇；否則拒絕資訊會指出
第一個沒有任何遭遇能承載的請求。

### Showdown 配置

「匯入貼上」會用 `ShowdownParsing.GetShowdownSets` 讀取 Showdown、Smogon 或 PKHeX 的配置，
支援 PKHeX 匯出的任何語言以及 PKHeX 的拼寫。沒有 `Level:` 行表示 100 級；`IVs:` 中缺失的 IV
為 31。

| 配置中的內容 | 結果 |
|---|---|
| 無法讀取的行，或遊戲缺少的物種、形態、特性、道具或招式，EV 超過 510 | 拒絕；不填入任何內容 |
| 朱與紫中的太晶屬性；劍與盾中的超極巨化和非 10 的極巨化等級 | 設定（[提供選項](#offer-options)） |
| 任何其他遊戲中的太晶屬性、超極巨化或極巨化等級，覺醒力量屬性；Let's Go 或傳說 阿爾宙斯中的 EV；傳說 Z-A 中的特性 | 略去，並附說明 |
| 沒有 `IVs:` 或 `Friendship:` 行 | 採用遭遇自身的數值 |
| 交換佇列中的多個配置 | 從貼上內容的選擇器中每次交換用一個，直到佇列上限；任何一次拒絕都會拒絕整次貼上 |
| 佇列之外的多個配置 | 第一個填入表單 |

劍與盾的神秘禮物會校驗 WC8 封印，並用 PKHeX 檢查物種、形態、招式和道具；自制卡片屬於分發
內容，而不是官方事件。

### Let's Go 的連線密碼

Let's Go 主持方的密碼是三個槽位，每個都從主機的十隻候選寶可夢中挑選，並以三個逗號分隔的
英文名傳給 `--code`。「開始」會等待這三個都設定好。

### 交換佇列

在一次座位上完成多次交換的工具最多接受六隻寶可夢，按順序提供：

| 工具 | 提供方式 | 最後一次之後 |
|---|---|---|
| 火紅/葉綠的主持和加入 | 隊伍檔案，`--trades N` | 主機拒絕（`PLAYER_CANCEL_TRADE`）並等待 Cancel 和 Yes；加入方取消 |
| Let's Go 主持 | `--offer`，然後 `--next-offer` | 不再回應交換（`pokeldn/lgpe/trade.py`） |
| Let's Go 加入 | 重複的 `--offer` | 不再回應交換 |
| 晶燦鑽石/明亮珍珠 | 重複的 `--offer` / `--trade-template` | 再次提供最後一個 |
| 傳說 阿爾宙斯 | 重複的 `--trade-box-record` / `--offer` | 再次提供最後一個 |
| 朱與紫 | 重複的 `--trade-offer` | 不再發送訊息（`pokeldn/sv/trade.py`、`done`） |
| 劍與盾 | 重複的 `--offer-file` | 再次提供最後一個 |
| 傳說 Z-A | 重複的 `--trade-offer` | 再次提供最後一個，配合 `--fresh-pid` 時使用新的 PID |

每次完成的交換都會呼叫 `pokeldn.ldn.show_done()`，它會閃爍 LED 並列印
`[done] trade N complete`；「會話」面板會對該行計數。N 大於 1 的交換會在輸出路徑上加字尾
寫入：`_tradeN_` 加物種（火紅/葉綠）、`.N`（朱與紫）、`_N`（晶燦鑽石/明亮珍珠主持）、`-N`
（傳說 Z-A、劍與盾）。

### 回換

每個交換主持和加入方都有的 `--trade-back`（應用中的「送回」開關）會在每次排隊的交換之後
追加一次交換，提供主機剛剛送來的寶可夢，這樣通過交換進化的寶可夢就會在主機上進化。玩家在
第二次交換中把我們的寶可夢換回去。一次交換之後，主機在其玩家再次發起交換之前不會再發送
任何內容（零售版《朱》的最後狀態是 `b90101b902b90280800100`，之後是 26 秒靜默，若其玩家
退出則離開），因此回程回合會向玩家顯示一張 `trade-back` 狀態卡，提示再次交換。
`pokeldn/trade_back.py` 儲存了這一順序：

| 交換 | 提供 |
|---|---|
| 1、3、5…… | 排隊的提供 1、2、3…… |
| 2、4、6…… | 前一次交換中主機發來的記錄，逐位元組原樣 |

返回的記錄絕不會接受 `--fresh-pid` 或任何其他提供改動。在最後一次排隊交換後停止的啟動器會
在兩倍次數後停止；會再次提供最後一個的啟動器則持續交替。

| 啟動器 | 記錄如何返回 |
|---|---|
| 原生主持 | `TradeBack` 代替線上夥伴（`pokeldn.online.link.Partner`）：主機在 `done` 之前的最後一次提供就是下一回合的記錄 |
| 火紅/葉綠的主持和加入 | 每個提供過的隊伍槽位會再次提供；TradeMons 已把收到的寶可夢放在那裡 [trade_scene.c:1054-1083]。一個會話最多進行 12 次交換 |
| 原生加入方 | `Rounds` 在啟動器自己的提供路徑中為每次交換選擇記錄 |

由 `bin/frlg_trade_host.py --over-ip --trade-back` 主持的模擬法文《火紅》在第 1 次交換中換出了
它的勇基拉，在第 2 次交換中換回，並使其進化為胡地；存檔保留了合法的胡地。由
`bin/swsh_host.py --ip-host --trade-back` 主持的模擬《盾》用它的熊徒弟換來了提供的大巖蛇，
然後在第 2 次交換中用大巖蛇換回熊徒弟，並按 B 離開。

`--trade-back` 會拒絕 `--online`、為接收方玩家制作的禮物，以及團體戰、巢穴和 Union Circle
模式。「神秘禮物 - 模擬」從不提供它。

### 結束一次執行

| 角色 | 結束條件 |
|---|---|
| 主持 | 主機在至少一次交換後離開（`pokeldn.ldn.left_after_trade`） |
| 火紅/葉綠主持 | 主機離開 |
| 加入方 | 主持關閉或移交其角色；朱與紫、傳說 阿爾宙斯和傳說 Z-A 在沒有交換的座位之後會再次搜尋 |

`--seconds` 和 `--hold` 用來限制主機始終不離開的執行。兩種角色下每個交換啟動器都有的
`--hold-after-trade N` 會在最後一次排隊交換後 N 秒離開座位或關閉會話
（`pokeldn.ldn.hold_after_trade_over`）。

## 本地檔案與釋出

`host.local.toml`、金鑰、筆記、日誌和構建輸出都留在本地；沒有任何生產預設值會讀取
`scratchpad/`。設定和準備好的提供內容位於平臺的資料資料夾中，可由 `POKELDN_DATA` 覆蓋。
清理通過 `pokeldn.app.storage` 執行（[本地儲存](gui.md#local-storage)）。

打包器會打包被跟蹤的執行時檔案、PKHeX 執行檔，以及 ESP32、S3、C3 和 C6 的韌體；
缺少映象會中止構建。Windows 構建會保留標準流以便記錄子程序日誌，同時隱藏控制台視窗。

## 驗證

```sh
pip install -r requirements-dev.txt
dotnet build -c Release services/pkhex -warnaserror
python -m pytest tests/ -q -W error -n auto --dist worksteal
```

CI 會在 Linux、macOS 和 Windows 上執行這些命令。釋出構建會對凍結的執行檔執行
`scripts/check_app.py`；它不需要金鑰或板子。
