# 代码结构

GUI 与命令行共享工具预设和宝可梦准备工作；游戏模块保留各自的线路格式和时序，共享组件则放在任何游戏目录之外。

| 位置 | 职责 |
| --- | --- |
| `pokeldn/app/` | 工具目录、参数组装、解析器检查、设置、路径与子进程 |
| `pokeldn/popup.py` | 程序在应用中显示的[弹窗](gui.md#pop-ups)；`pokeldn/app/popups.py` 决定显示哪些 |
| `pokeldn/pokemon.py` | PKHeX 服务、导入、最终提供校验和接收到的文件 |
| `pokeldn/gifts.py` | 共享的[神秘礼物文件](gifts.md)封装、读取器、写入器和原生转换 |
| `pokeldn/receiver_gift.py` | 交换主持方为接收方主机存档制作的神秘礼物宝可梦（[为接收方玩家制作](gift_simulated.md#made-for-the-receiving-player)） |
| `services/pkhex/` | 固定版本的 PKHeX.Core；合法遭遇生成与兼容性检查 |
| `pokeldn/ldn/` | 无线传输、IP、Pia、可靠性与信道表 |
| `pokeldn/online/` | [在线交换](online.md)：中继、匹配和加密的伙伴通道 |
| `pokeldn/gba/` | GBA 无线连接协议 |
| `pokeldn/gen8.py`, `pokeldn/gen9.py` | 共享的宝可梦记录编解码器 |
| `pokeldn/<game>/` | 游戏标识、消息、状态机和协议变体 |
| `pokeldn/launcher.py` | 每个 `bin/` 启动器共享的标志（`--keys`、`--phy`、`--capture`、Linux 接口名、`--ip-host`/`--our-ip`），以及被扫描网络的一行描述 |
| `bin/` | 解析器与会话编排 |
| `gui/` | 视图、控件、主题和板子控制 |

应用一次只运行一个会话，因为一块板子只服务一个进程。在另一个工具上点「开始」会停止
正在运行的会话，等它退出后再启动；「开始」也会等待正在进行的刷写。

## 宝可梦准备

每个交换启动器在打开无线模块之前，会先通过 PKHeX 服务准备提供的文件。不兼容的格式、
不可用的物种和非法的最终记录都会被拒绝。会话的训练家身份绝不会覆盖导入宝可梦的原训练家。

| 行为 | 规则 |
|---|---|
| 分析不完整 | `LegalityAnalysis.Parsed` 为 false 时会重启辅助进程，并在服务锁下重试一次；第二次失败则抛出异常 |
| 全新身份 | 可选启用新的 PID 和加密常数；因此变得非法的记录会保留自己的，并记录 `the offer kept its own PID` |
| 闪光、单一性别 | 向遭遇请求，因此第三世代的 PID 会保留其 RNG 关联 |
| 随机取值 | PID、IV 和野生槽位的等级，每次遭遇最多八次取值 |
| 进化后的物种 | 当没有以捕获形态匹配的遭遇时，提升到其进化等级；无性别时（脱壳忍者）取进化后的性别，遭遇的形态不存在时（葱游兵）取形态 0 |

在等级或物种变更后失败的记录会按顺序修复，每一步都基于上一步的结果；保留第一个合法
结果：

1. 仅限 HOME 的事件（剑与盾中的捷拉奥拉、美录梅塔）在设置为「made」时会获得 HOME 追踪器
   （[HOME 追踪器设置](gui.md#the-home-tracker-setting)）。
2. 招式、回忆招式、TM/TR 记录标志、附加招式与精通标志，以及传说 阿尔宙斯的尺寸都会
   重新适配。
3. 进化后记录的特性会在其捕获时的槽位中刷新。这一步必须在重新适配之后（传说 Z-A 中的
   赛富豪）。
4. 没有经手训练家的记录会获得 `POKELDN`。
5. 计数型进化（击中要害次数、受到的伤害、愤怒之拳使用次数、硬币）从它的计数开始。
6. 晶灿钻石与明亮珍珠中的美丽度进化（美纳斯，170）会设置该美丽度，以及它的宝芬所暗示的
   最低光泽度。

无法满足的请求会被拒绝并给出原因。普通构建只在少数物种上失败：晶灿钻石与明亮珍珠 2 种
（时拉比、代欧奇希斯），剑与盾 2 种（蒂安希、美录坦），传说 Z-A 1 种（美纳斯，其游戏记录
拒绝华丽大赛数值），朱与紫 31 种（仅限 HOME 的传说宝可梦，以及诡角鹿——PKHeX 没有为其
提供第九世代进化）。

未指定形态的请求会取第一个能构建成功的形态。仅以较晚形态存在的物种：

| 游戏 | 物种 | PKHeX 可构建的形态 |
|---|---|---|
| 剑与盾 | 基格尔德 | 10%-C、50%-C（群聚变形） |
| 剑与盾 | 玛机雅娜 | 原始之色，一个事件 |
| 传说 阿尔宙斯 | 骑拉帝纳 | 起源 |
| 朱与紫 | 月月熊 | 血月 |
| 传说 Z-A | 基格尔德 | 10%-C、50%-C、完全体 |
| 传说 Z-A | 粉蝶虫、粉蝶蛹 | 花园花纹、草地花纹 |
| 传说 Z-A | 彩粉蝶 | 花园花纹、草地花纹、大洋花纹 |

### 遭遇顺序

一次构建会逐个版本尝试 PKHeX 的遭遇（`EncounterMovesetGenerator`），玩家自己的版本优先；
每个版本内按种类尝试，每种只取前 80 个遭遇：

| 顺序 | 种类 | 由此构建的记录 |
|---|---|---|
| 1 | 野生槽位 | 在槽位的地点和等级捕获，任意可捕获的球 |
| 2 | 固定遭遇 | 礼物、传说宝可梦、团体战或极巨大冒险宝可梦 |
| 3 | 游戏内交换 | NPC 的宝可梦 |
| 4 | 蛋 | 孵化，使用其亲代遗传的球 |
| 5 | 神秘礼物 | 排在所有其他种类和版本之后，因为事件的固定 PID 会让新 PID 的提供变得非法 |

Let's Go 皮卡丘与伊布在自身版本之后还会尝试 GO 版本：GO Park 园区存放着从 Pokemon GO
带来的宝可梦，其中包括美录坦、美录梅塔和阿罗拉形态。那里的遭遇选择是某一种 GO 遭遇
（野生、团体战、调查等），覆盖 PKHeX 列出的每个日期窗口。

低于进化等级的已进化宝可梦会先在 100 级测试，然后用二分法找出最低的合法等级。朱与紫中的
蜜集大蛇只在零散的等级上合法。

存档会清除它收到的、原训练家的名字、ID 和性别都与自己相同的宝可梦的经手训练家
（[交换会向收到的记录写入什么](za.md#what-the-trade-writes-into-a-received-record)）。
如果某个构建只有带经手训练家时 PKHeX 才接受（例如玛机雅娜这样的 HOME 礼物），且其原训练家
就是玩家，则会以原训练家 POKELDN、玩家作为经手训练家来制作；「让我成为它的原训练家」会
拒绝这样的文件。

### 提供选项

一次构建可以指定形态、性格、特性、性别、携带道具、球、亲密度、最多四个招式、IV 和努力值、
一个遭遇；在传说 阿尔宙斯和传说 Z-A 中还可指定它是否为头目，在剑与盾中可指定超极巨化因子和
极巨化等级，在朱与紫中可指定太晶属性。招式、形态、遭遇和头目会缩小遭遇搜索范围；性格、
特性、性别和 IV 会进入遭遇条件。当遭遇得到的是别的结果时，记录会按玩家的做法修改：

| 差异 | 修改 |
|---|---|
| 性格 | 薄荷，第八世代起 |
| 特性 | 胶囊或膏药 |
| 要求为 31 的 IV | 极限特训，在 100 级（第七、八世代）或 50 级（第九世代） |
| 形态 | 在玩家可改变形态的物种上设置，例如洛托姆 |

携带道具、球、亲密度、努力值、糖饰、超极巨化因子、极巨化等级和太晶属性都在构建之后设置，
就像使用极巨汤、极巨糖果和太晶碎块一样。糖饰是霜奶仙的形态参数，0 为草莓糖饰，6 为缎带
糖饰；太晶属性是覆盖字节，星晶为 99（`TeraTypeUtil.SetTeraType`）。第三、四世代中高于 100 的
EV 需要相遇后获得的经验，因此记录会得到一点经验值。传说 阿尔宙斯的努力等级按游戏内显示的
取值，存储前会减去 IV 偏置（IV 20 起为 1，26 起为 2，31 为 3）。

亲密度属于原训练家。只有接收方主机的玩家就是原训练家时，主机才会保留它，因此「设置 →
[你的训练家](gui.md#your-trainer)」必须是玩家的信息；每部作品的交换页面会说明一次交换会
重写什么。火红/叶绿会把收到的每只非蛋宝可梦设为 70 [trade_scene.c:1071]。

| 选项 | 列出的条件 |
|---|---|
| 球 | PKHeX 至少在一个遭遇中允许它 |
| 头目 | 传说 阿尔宙斯或传说 Z-A 中该物种有头目遭遇（`IAlphaReadOnly.IsAlpha`） |
| 特性 | 存在携带它的合法构建；传说 Z-A 不列出任何特性 |
| 携带道具 | 该游戏中已解禁的携带道具；Let's Go 和传说 阿尔宙斯没有 |
| 努力值 | 每项 EV 252、总和 510；Let's Go 为 AV，每项 200；传说 阿尔宙斯为努力等级，每项 10 |
| 糖饰 | 霜奶仙，且该游戏的记录会保留形态参数 |
| 超极巨化 | 该物种和形态满足 `Gigantamax.CanToggle` |
| 极巨化等级 | 剑与盾，苍响、藏玛然特和无极汰那除外 |
| 太晶属性 | 朱与紫，且该物种的太晶属性可改变（`TeraTypeUtil.CanChangeTeraType`）；18 种属性和星晶 |

「最大 IV」把六项都设为 31，「最大亲密度」为 255。「最大 EV」会把每项属性填到上限；在总和
510 之下，该物种基础数值最高的两项各得 252，第三项得剩下的 6 点。

### 选择遭遇

`encounters` 会列出该物种和形态的构建可能来自的每一个遭遇，按[遭遇顺序](#encounter-order)
排列，并分组：同一版本、同一地点的同一种遭遇，其所有槽位和等级合在一起；或一张神秘礼物
卡片（`EncounterKey`）。每个分组带有地点名（`ILocation.GetEncounterLocation`，礼物则为卡片的
标题）、等级范围、作为进化前形态相遇时的物种，以及是否可以为闪光。给定分组键的构建只会
尝试该分组；构建的回复会给出它的 `encounter_place`。

会保留[遭遇顺序](#encounter-order)中第一个能合法承载所有请求的遭遇；否则拒绝信息会指出
第一个没有任何遭遇能承载的请求。

### Showdown 配置

「导入粘贴」会用 `ShowdownParsing.GetShowdownSets` 读取 Showdown、Smogon 或 PKHeX 的配置，
支持 PKHeX 导出的任何语言以及 PKHeX 的拼写。没有 `Level:` 行表示 100 级；`IVs:` 中缺失的 IV
为 31。

| 配置中的内容 | 结果 |
|---|---|
| 无法读取的行，或游戏缺少的物种、形态、特性、道具或招式，EV 超过 510 | 拒绝；不填入任何内容 |
| 朱与紫中的太晶属性；剑与盾中的超极巨化和非 10 的极巨化等级 | 设置（[提供选项](#offer-options)） |
| 任何其他游戏中的太晶属性、超极巨化或极巨化等级，觉醒力量属性；Let's Go 或传说 阿尔宙斯中的 EV；传说 Z-A 中的特性 | 略去，并附说明 |
| 没有 `IVs:` 或 `Friendship:` 行 | 采用遭遇自身的数值 |
| 交换队列中的多个配置 | 从粘贴内容的选择器中每次交换用一个，直到队列上限；任何一次拒绝都会拒绝整次粘贴 |
| 队列之外的多个配置 | 第一个填入表单 |

剑与盾的神秘礼物会校验 WC8 封印，并用 PKHeX 检查物种、形态、招式和道具；自制卡片属于分发
内容，而不是官方事件。

### Let's Go 的连接密码

Let's Go 主持方的密码是三个槽位，每个都从主机的十只候选宝可梦中挑选，并以三个逗号分隔的
英文名传给 `--code`。「开始」会等待这三个都设置好。

### 交换队列

在一次座位上完成多次交换的工具最多接受六只宝可梦，按顺序提供：

| 工具 | 提供方式 | 最后一次之后 |
|---|---|---|
| 火红/叶绿的主持和加入 | 队伍文件，`--trades N` | 主机拒绝（`PLAYER_CANCEL_TRADE`）并等待 Cancel 和 Yes；加入方取消 |
| Let's Go 主持 | `--offer`，然后 `--next-offer` | 不再回应交换（`pokeldn/lgpe/trade.py`） |
| Let's Go 加入 | 重复的 `--offer` | 不再回应交换 |
| 晶灿钻石/明亮珍珠 | 重复的 `--offer` / `--trade-template` | 再次提供最后一个 |
| 传说 阿尔宙斯 | 重复的 `--trade-box-record` / `--offer` | 再次提供最后一个 |
| 朱与紫 | 重复的 `--trade-offer` | 不再发送消息（`pokeldn/sv/trade.py`、`done`） |
| 剑与盾 | 重复的 `--offer-file` | 再次提供最后一个 |
| 传说 Z-A | 重复的 `--trade-offer` | 再次提供最后一个，配合 `--fresh-pid` 时使用新的 PID |

每次完成的交换都会调用 `pokeldn.ldn.show_done()`，它会闪烁 LED 并打印
`[done] trade N complete`；「会话」面板会对该行计数。N 大于 1 的交换会在输出路径上加后缀
写入：`_tradeN_` 加物种（火红/叶绿）、`.N`（朱与紫）、`_N`（晶灿钻石/明亮珍珠主持）、`-N`
（传说 Z-A、剑与盾）。

### 回换

每个交换主持和加入方都有的 `--trade-back`（应用中的「送回」开关）会在每次排队的交换之后
追加一次交换，提供主机刚刚送来的宝可梦，这样通过交换进化的宝可梦就会在主机上进化。玩家在
第二次交换中把我们的宝可梦换回去。一次交换之后，主机在其玩家再次发起交换之前不会再发送
任何内容（零售版《朱》的最后状态是 `b90101b902b90280800100`，之后是 26 秒静默，若其玩家
退出则离开），因此回程回合会向玩家显示一张 `trade-back` 状态卡，提示再次交换。
`pokeldn/trade_back.py` 保存了这一顺序：

| 交换 | 提供 |
|---|---|
| 1、3、5…… | 排队的提供 1、2、3…… |
| 2、4、6…… | 前一次交换中主机发来的记录，逐字节原样 |

返回的记录绝不会接受 `--fresh-pid` 或任何其他提供改动。在最后一次排队交换后停止的启动器会
在两倍次数后停止；会再次提供最后一个的启动器则持续交替。

| 启动器 | 记录如何返回 |
|---|---|
| 原生主持 | `TradeBack` 代替在线伙伴（`pokeldn.online.link.Partner`）：主机在 `done` 之前的最后一次提供就是下一回合的记录 |
| 火红/叶绿的主持和加入 | 每个提供过的队伍槽位会再次提供；TradeMons 已把收到的宝可梦放在那里 [trade_scene.c:1054-1083]。一个会话最多进行 12 次交换 |
| 原生加入方 | `Rounds` 在启动器自己的提供路径中为每次交换选择记录 |

由 `bin/frlg_trade_host.py --over-ip --trade-back` 主持的模拟法文《火红》在第 1 次交换中换出了
它的勇基拉，在第 2 次交换中换回，并使其进化为胡地；存档保留了合法的胡地。由
`bin/swsh_host.py --ip-host --trade-back` 主持的模拟《盾》用它的熊徒弟换来了提供的大岩蛇，
然后在第 2 次交换中用大岩蛇换回熊徒弟，并按 B 离开。

`--trade-back` 会拒绝 `--online`、为接收方玩家制作的礼物，以及团体战、巢穴和 Union Circle
模式。「神秘礼物 - 模拟」从不提供它。

### 结束一次运行

| 角色 | 结束条件 |
|---|---|
| 主持 | 主机在至少一次交换后离开（`pokeldn.ldn.left_after_trade`） |
| 火红/叶绿主持 | 主机离开 |
| 加入方 | 主持关闭或移交其角色；朱与紫、传说 阿尔宙斯和传说 Z-A 在没有交换的座位之后会再次搜索 |

`--seconds` 和 `--hold` 用来限制主机始终不离开的运行。两种角色下每个交换启动器都有的
`--hold-after-trade N` 会在最后一次排队交换后 N 秒离开座位或关闭会话
（`pokeldn.ldn.hold_after_trade_over`）。

## 本地文件与发布

`host.local.toml`、密钥、笔记、日志和构建输出都留在本地；没有任何生产默认值会读取
`scratchpad/`。设置和准备好的提供内容位于平台的数据文件夹中，可由 `POKELDN_DATA` 覆盖。
清理通过 `pokeldn.app.storage` 执行（[本地存储](gui.md#local-storage)）。

打包器会打包被跟踪的运行时文件、PKHeX 可执行文件，以及 ESP32、S3、C3 和 C6 的固件；
缺少镜像会中止构建。Windows 构建会保留标准流以便记录子进程日志，同时隐藏控制台窗口。

## 验证

```sh
pip install -r requirements-dev.txt
dotnet build -c Release services/pkhex -warnaserror
python -m pytest tests/ -q -W error -n auto --dist worksteal
```

CI 会在 Linux、macOS 和 Windows 上运行这些命令。发布构建会对冻结的可执行文件运行
`scripts/check_app.py`；它不需要密钥或板子。
